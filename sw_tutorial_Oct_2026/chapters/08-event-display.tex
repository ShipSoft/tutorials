\section{Three inputs and nothing else}

\repo{sea-cucumber} takes a GeoModel \file{.db}, a data file in the SHiP data
model, and optionally a view configuration in TOML. It links no simulation or
analysis code, so it can inspect supported event-oriented files regardless of their producer;
it does not support every on-disk layout. From the \texttt{events} RNTuple it reads the fields
\texttt{mc\_particles}, \texttt{sim\_hits}, \texttt{sim\_particles} and
\texttt{rec\_particles}, and tolerates any of them being absent.

It has two front ends sharing one core:

\begin{description}[style=nextline]
  \item[the REve display] ROOT's web-based event display, one event at a
    time, started with \cmd{pixi cvmfs run};
  \item[the web display] a three.js page in your browser: the C++ side
    first writes the geometry and events to JSON files, which the page then
    renders. You can arrange any number of zoomed views and save the layout.
\end{description}

Following the ALICE O\textsuperscript{2} event-display design, the C++ side
does all the interpretation (reading the geometry, choosing colours,
tessellating shapes), and the viewers only draw.

\begin{note}
\pkg{sea-cucumber} reads simulation output. It does not read the per-detector
collections written by \pkg{Shannon}, so digitised hits cannot be displayed
yet.
\end{note}

\section{The REve display}

\begin{exercise}{Your first muons}
From the \file{sea-cucumber} directory:
\begin{shell}
pixi cvmfs run --geometry ../work/ship_geometry.db \
             --data ../work/muon_gun.root \
             --view views/default.toml --event 0
\end{shell}
REve opens in a browser window (on lxplus, see the organiser's instructions
below). Rotate and zoom the main view. Find where the muon starts, at the
back of the muon shield, and follow it through the decay volume and the
detectors. Where does it end? Step through a few events (\cmd{--event 1},
\cmd{--event 2}, \ldots) and compare which detectors have hits.
\end{exercise}

\begin{organisernote}
REve is a web page served by ROOT. On lxplus it either opens a browser through
the X11 connection (slow) or prints the address of the page, whose port must
then be forwarded like the one of the web display. \tbd{settle the REve
recipe on lxplus with the sea-cucumber developers, e.g.\ a fixed
\texttt{WebGui.HttpPort} per participant and an SSH tunnel, and write it
here}
\end{organisernote}

\begin{checkpoint}
One track per event starting at $z=27$\,m, close to the beam axis, with hits
in the UBT, in the four straw stations and, for most muons, in the timing
detector and the calorimeter.
\end{checkpoint}

\begin{solution}
At 20\,mrad or less from the beam, nearly every muon stays inside the decay
volume, crosses the UBT in front of it and the straw stations behind it, and
is bent in $x$ by the spectrometer magnet between stations 2 and 3. Muons
between 10 and 100\,GeV do not stop in the calorimeter: they leave through
its back. SBT hits are rare and usually come from secondaries.
\Cref{ch:analysis} counts all this.
\end{solution}

\begin{pitfall}
The geometry has about a million volumes. Reading it takes several seconds
at every start, and drawing all of it would make the display unusable, which
is why \file{views/default.toml} excludes the straws, tiles and SBT cells.
For repeated use, convert the geometry once into a cache:
\begin{shell}
pixi cvmfs geo-cache --geometry ../work/ship_geometry.db \
    --view views/default.toml
pixi cvmfs run --geo-cache geocache --geometry ../work/ship_geometry.db \
             --data ../work/muon_gun.root --event 0
\end{shell}
\end{pitfall}

\section{The web display}

\begin{exercise}{All events in the browser}
Produce the display files for all events:
\begin{shell}
pixi cvmfs web-data --geometry ../work/ship_geometry.db \
                  --data ../work/muon_gun.root \
                  --view views/default.toml --events all
\end{shell}
An lxplus node is shared by many people, so each of you serves the page on a
port of your own, visible only on the node itself (\cmd{pixi cvmfs web}
would use port 8080 for everybody):
\begin{shell}
PORT=$((8000 + $(id -u) % 1000)); hostname; echo $PORT
pixi cvmfs python -m http.server $PORT --bind 127.0.0.1 --directory web
\end{shell}
On your own machine, in a second terminal, open a tunnel to that node and
port (\texttt{lxplusNNN} is what \cmd{hostname} printed):
\begin{shell}
ssh -N -L 8080:localhost:<PORT> <you>@lxplusNNN.cern.ch
\end{shell}
Open \url{http://localhost:8080} in your browser. Step through the events from the sidebar.
Draw a rectangle on the main view to open a zoomed view of the straw
stations; save the layout.
\end{exercise}

\begin{note}
The web page loads three.js from a public CDN, so your browser needs
internet access; the \pkg{sea-cucumber} manual explains how to serve it
locally instead.
\end{note}

\section{View configuration}

A view file has global settings, a \texttt{[geometry]} table (which volumes to
draw and how), \texttt{[hits]} and \texttt{[decay]} tables (event styling),
and any number of \texttt{[[region]]} tables, each a zoomed view with its own
window and camera. For example, a side view of the spectrometer:

\begin{tomlcode}
[[region]]
name   = "Spectrometer"
title  = "Spectrometer (side view)"
zmin   = 82000.0          # mm
zmax   = 96000.0
camera = "xz"             # side view, looking along y
max_shapes = 6000
\end{tomlcode}

Geometry colours are assigned by \texttt{[[geometry.style]]} rules, matched
as substrings of volume names; the first matching rule wins. The full list of
keys is in \file{docs/manual.md} in the repository.

\begin{exercise}{A view for the spectrometer}
Copy \file{views/default.toml} to \file{views/spectrometer.toml} and edit the copy
in your editor:
\begin{enumerate}
  \item The style rules match names like \texttt{DecayVolume} or
        \texttt{Tracker}. Compare them with the volume names you found in
        \cref{ch:geometry}: which rules still apply? Change them to match the
        \texttt{/SHiP/\ldots} names.
  \item Add a region showing the straw stations and the magnet in the
        horizontal $xz$ projection (viewed along $y$): \texttt{camera = "xz"},
        $z$ from 83\,000 to 97\,000\,mm.
\end{enumerate}
Display a few events with \cmd{--view views/spectrometer.toml}.
\end{exercise}

\begin{solution}
Style matching is a case-sensitive substring test, so
\texttt{DecayVolume}, \texttt{Tracker}, \texttt{Timing}, \texttt{ECAL},
\texttt{HCAL}, \texttt{MuonShield} and \texttt{Target} match none of the
current names. Replacements: \texttt{decay\_volume}, \texttt{trackers},
\texttt{timing\_detector}, \texttt{calorimeter}, \texttt{muon\_shield},
\texttt{target}, \texttt{magnet}, \texttt{sbt}. The region:
\begin{tomlcode}
[[region]]
name = "Spectrometer"
title = "Straw stations and magnet (top view)"
zmin = 83000.0
zmax = 97000.0
camera = "xz"
max_shapes = 3000
\end{tomlcode}
\end{solution}

\begin{organisernote}
Style rules are matched with \texttt{std::string::find} in
\file{src/ViewConfig.cxx}, i.e.\ case-sensitively, so none of the default
styles matches the current \texttt{/SHiP/\ldots} names and every volume gets
the default colour or the hashed blue/cream fallback. Worth an issue (or a
pull request updating \file{views/default.toml}) on \repo{sea-cucumber}
before the tutorial; if it is fixed, drop part~1 of the exercise.
\end{organisernote}

\begin{exercise}[colback=white]{Optional: with and without field}
If you made \file{muon\_gun\_nofield.root} in \cref{ex:nofield}, match
the physical event using \field{event\_number}, then display its entry from
each file side by side in two browser tabs. Where do the tracks start to
differ, and in which direction is the $\mu^-$ bent? With
\file{muon\_gun\_mup.root} (\cref{ex:mup}), do the same for the $\mu^+$.
The \cmd{--event} option selects an RNTuple entry index, not necessarily the
stored \field{event\_number}; multithreaded outputs can have different order.
\end{exercise}
